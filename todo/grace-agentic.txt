WHY
TRIGZI is two things: a food-safety pipeline and the agent-management system that
was iterated to its current hyperfunctional state while building it. The tools
assume the estate root is the cwd and that TRIGZI's layout is the only layout.
QUANTUM, CGIOS and every future estate now consume that system through symlinks
(QUANTUM/tools -> ../TRIGZI/tools, QUANTUM/docs -> ../TRIGZI/docs). That works
until TRIGZI moves, is archived, or diverges. AGENTIC/ is the new single source:
"import from here." This todo is the migration spec. It is a chunked job, not a
weekend.

CONSUMPTION MODEL (decide first, then everything follows)
  Option A - symlinks: <estate>/tools -> ../AGENTIC/tools, <estate>/docs/agents
             -> ../AGENTIC/docs/agents, etc. Zero code change; breaks on any
             move; git records links not content.
  Option B - a Makefile target in each estate: `make agentic` that syncs or
             links; AGENTIC/README documents the contract.
  Option C - AGENTIC is a git submodule of each estate. Clean, versioned,
             heavier ceremony; TRIGZI already uses submodules so the muscle
             exists.
  Recommendation: C for docs+tools (versioned import), per-estate home/ and
  queues stay local. Ask James before choosing - 30 seconds beats an hour.
